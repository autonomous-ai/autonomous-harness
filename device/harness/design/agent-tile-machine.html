Agent tile — saying which machine

The carousel spans machines now, but an agent's own tile never says which one it is on. You can reach it by swiping past agents from three computers and the tile looks identical either way.

The tile is a tight space, and the budget is the whole design problem. Measured from ui_screens.c, not estimated:

  • y < 44 — swallowed by touch.c for the switcher pull-down. Fine for a label, useless for anything tappable.
  • y 22–58 — the bell (LV_ALIGN_TOP_MID, 0, 22), but only when there are unread turns. Anything centred here collides sometimes, which is worse than always.
  • y 69–109 — the floating chip row [mark] [Model] [Effort].
  • y 117–165 — the agent name, geist_med_38, one line, ellipsised.
  • The glass is 307 px wide at y=58, 331 at y=69, 394 at y=109 — a round face, so anything up high is also narrow.

So there is no free real estate up top: the only truly unclaimed band is y 44–69, which is 25 px, and it disappears under the bell whenever a turn finishes.

D A, remote only~30 px, remote tiles onlyyes Two tile heights instead of one. The chip row already appears conditionally, so the layout copes — but it is a second reason for the body to move, and those interact.

Why not the top band. y 44–69 is the only unclaimed space and it is 25 px — enough for one geist_reg_20 line. But the bell lands at y 22–58 whenever a turn finishes, so that line would be clear most of the time and collide exactly when the user has just been notified. A layout that is correct until something happens is worse than one that always costs 30 px.

Why "not this computer" and not "remote". If D wins, the line should say the machine's name, and the local case should show nothing at all — the Machines wheel already treats the cabled machine as the unmarked default and names it "This computer" only when it has a row of its own (machine_meta_line). Marking the exception is the same rule, one screen along.

The data is already there. project_t.machine_id / .machine arrive with the agent list, and cable_client_machine_id() is this computer's id — so every option above is a rendering change with no new wire field. An older daemon sends "", which matches nothing and simply renders as today.
