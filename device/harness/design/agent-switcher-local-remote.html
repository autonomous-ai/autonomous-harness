Agent switcher — telling local from remote

Swipe down from any carousel page and this list opens (ui_switch_open → switch_rebuild in main/ui/ui_screens.c). Since the carousel started spanning every machine, the list mixes agents from this computer with agents reached over the cloud — and every row looks the same, so there is nothing to tell them apart at a glance.

Line two already carries the machine name. All five options below change only how that line is presented; none of them adds a line or changes the row's height, except D, which spends one header row per machine.

The device already has a word for this. The Machines wheel calls the cabled machine "This computer" (machine_meta_line, ui_screens.c:6396) — chosen because the cable is the evidence and that is the only row that can claim it. Options D and E reuse that exact phrase rather than inventing a second vocabulary for the same fact.

Rendered at true 466 px and scaled, with the real geometry: 384-wide column, 16 px radius, 16/10 padding, 28 px name over a 25 px machine line. Fonts are approximated — the device uses Geist.

E words + dotwords + shape + huenone Local rows stop naming their machine — fine while one computer per machine holds, which is an invariant of the product, not a coincidence.

How the firmware would know. Every row already carries it: project_t.machine_id arrives with the agent list, and cable_client_machine_id() is the cabled computer's own id. Local is strcmp(p->machine_id, cable_client_machine_id()) == 0 — no new wire field and no new RPC. A daemon too old to send machineId sends "", which matches nothing, so every row simply falls back to today's appearance rather than claiming to be remote.

All five keep the existing busy rule. An agent mid-turn still shows its name in COL_VOICE green (payments above). That is a different fact from where it lives, which is why the local marker is on line two and never on the name.
